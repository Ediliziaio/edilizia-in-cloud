VISIONE DEL PRODOTTO
────────────────────
Il modulo Tesoreria permette alle aziende di collegare i propri conti bancari
tramite Open Banking (PSD2) e avere su un'unica piattaforma:
  • Saldo in tempo reale di tutti i conti
  • Feed unificato di transazioni categorizzate automaticamente
  • Cash flow mensile (entrate/uscite/netto) con grafico storico
  • (futuro) Riconciliazione con fatture e costi registrati

PROVIDER API: GoCardless Bank Account Data (ex Nordigen)
  • 2.400+ banche in 30+ paesi EU, incluse tutte le principali italiane
    (Intesa SanPaolo, UniCredit, Banco BPM, BPER, Fineco, Mediolanum, Widiba…)
  • PSD2-compliant · Sola lettura · Non può eseguire pagamenti
  • Free tier: 50 requisizioni/giorno · poi pay-per-use
  • Documentazione: https://developer.gocardless.com/bank-account-data/overview
  • Registrazione: https://bankaccountdata.gocardless.com/overview/
  • Sandbox per test: usa istituto "SANDBOXFINANCE_SFIN0000", credenziali "test"/"test"

ARCHITETTURA SICUREZZA
──────────────────────
  SuperAdmin → configura credenziali GoCardless in platform_settings (server-only)
  ↓
  Azienda → seleziona banca → redirect sicuro a pagina login banca (GoCardless)
  ↓
  GoCardless → callback con requisition_id → edge function completa la connessione
  ↓
  Edge functions (service role) → sincronizzano saldi e transazioni (token MAI esposti)
  ↓
  Dashboard Tesoreria → KPI, conti, feed transazioni, cash flow

REGOLE DI SICUREZZA (NON NEGOZIABILI):
  ✗ Le credenziali GoCardless NON toccano mai il frontend
  ✗ I token bancari sono gestiti SOLO dalle edge functions (service role)
  ✗ RLS garantisce isolamento completo tra aziende
  ✓ redirect_url validato server-side per prevenire XSS/SSRF
  ✓ Token GoCardless (24h) con retry automatico se scaduto durante sync

-- get_treasury_summary: KPI aggregati per la dashboard Overview
-- CORRETTO: WHERE filtra già per company_id, nessun GROUP BY necessario
CREATE OR REPLACE FUNCTION public.get_treasury_summary(p_company_id uuid)
RETURNS TABLE (
  total_balance      numeric,
  accounts_count     bigint,
  connections_count  bigint,
  monthly_income     numeric,
  monthly_expenses   numeric,
  monthly_net        numeric,
  last_sync_at       timestamptz
)
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$
  SELECT
    COALESCE((
      SELECT SUM(ba.current_balance)
      FROM public.bank_accounts ba
      WHERE ba.company_id = p_company_id AND ba.is_active = true
    ), 0) AS total_balance,

    (SELECT COUNT(*) FROM public.bank_accounts ba
     WHERE ba.company_id = p_company_id AND ba.is_active = true
    ) AS accounts_count,

    (SELECT COUNT(*) FROM public.bank_connections bc
     WHERE bc.company_id = p_company_id AND bc.status = 'active'
    ) AS connections_count,

    COALESCE((
      SELECT SUM(t.amount)
      FROM public.bank_transactions t
      WHERE t.company_id = p_company_id
        AND t.transaction_type = 'credit'
        AND t.booking_date >= date_trunc('month', CURRENT_DATE)
        AND t.status = 'booked'
    ), 0) AS monthly_income,

    COALESCE((
      SELECT SUM(ABS(t.amount))
      FROM public.bank_transactions t
      WHERE t.company_id = p_company_id
        AND t.transaction_type = 'debit'
        AND t.booking_date >= date_trunc('month', CURRENT_DATE)
        AND t.status = 'booked'
    ), 0) AS monthly_expenses,

    COALESCE((
      SELECT SUM(t.amount)
      FROM public.bank_transactions t
      WHERE t.company_id = p_company_id
        AND t.booking_date >= date_trunc('month', CURRENT_DATE)
        AND t.status = 'booked'
    ), 0) AS monthly_net,

    (SELECT MAX(bc.last_sync_at) FROM public.bank_connections bc
     WHERE bc.company_id = p_company_id
    ) AS last_sync_at;
$$;

-- get_cash_flow_by_month: dati mensili per il grafico
CREATE OR REPLACE FUNCTION public.get_cash_flow_by_month(
  p_company_id uuid,
  p_months     int DEFAULT 6
)
RETURNS TABLE (
  month    text,
  income   numeric,
  expenses numeric,
  net      numeric
)
LANGUAGE sql STABLE SECURITY DEFINER SET search_path = public
AS $$
  SELECT
    TO_CHAR(date_trunc('month', t.booking_date), 'YYYY-MM') AS month,
    COALESCE(SUM(t.amount) FILTER (WHERE t.transaction_type = 'credit'), 0)     AS income,
    COALESCE(SUM(ABS(t.amount)) FILTER (WHERE t.transaction_type = 'debit'), 0) AS expenses,
    COALESCE(SUM(t.amount), 0)                                                   AS net
  FROM public.bank_transactions t
  WHERE t.company_id = p_company_id
    AND t.booking_date >= date_trunc('month', CURRENT_DATE)
      - make_interval(months => p_months - 1)
    AND t.status = 'booked'
  GROUP BY date_trunc('month', t.booking_date)
  ORDER BY 1 ASC;
$$;

-- Trigger updated_at (usa funzione esistente del progetto se presente,
-- altrimenti crea update_updated_at_column)
CREATE OR REPLACE FUNCTION public.banking_set_updated_at()

BEGIN NEW.updated_at = now(); RETURN NEW; END; $$;

CREATE TRIGGER trg_bank_accounts_updated_at

  BEFORE UPDATE ON public.bank_provider_configs

  import { getPlatformSetting } from "./getPlatformSetting.ts";

  const GC_BASE = "https://bankaccountdata.gocardless.com/api/v2";

  // Ottieni un token GoCardless (valido 24h)
  // IMPORTANTE: token ottenuto fresh ad ogni invocazione per semplicità.
  // In produzione si può cachare su platform_settings per 23h.
  export async function getGoCardlessToken(): Promise<string> {
    const secretId  = await getPlatformSetting("bank_gocardless_secret_id");
    const secretKey = await getPlatformSetting("bank_gocardless_secret_key");

    if (!secretId || !secretKey) {
      throw new Error("GoCardless non configurato. Contatta il SuperAdmin.");
    }

    const res = await fetch(`${GC_BASE}/token/new/`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "Accept": "application/json" },
      body: JSON.stringify({ secret_id: secretId, secret_key: secretKey }),
    });

    if (!res.ok) {
      const err = await res.json().catch(() => ({}));
      throw new Error(`GoCardless auth fallita: ${err.detail || res.status}`);
    }

    const { access } = await res.json();
    return access;
  }

  // Chiamata API GoCardless con retry automatico su 401 (token scaduto)
  export async function gcFetch(
    path: string,
    token: string,
    options: RequestInit = {},
    retry = true
  ): Promise<any> {
    const res = await fetch(`${GC_BASE}${path}`, {
      ...options,
      headers: {
        "Authorization": `Bearer ${token}`,
        "Content-Type": "application/json",
        "Accept": "application/json",
        ...(options.headers || {}),
      },
    });

    if (res.status === 401 && retry) {
      // Token scaduto: rigenera e riprova UNA volta
      console.warn("[GoCardless] Token scaduto, rigenerazione...");
      const newToken = await getGoCardlessToken();
      return gcFetch(path, newToken, options, false);  // no retry the second time
    }

    if (!res.ok) {
      const err = await res.json().catch(() => ({}));
      throw new Error(`GoCardless ${path} → ${res.status}: ${JSON.stringify(err)}`);
    }

    return res.json();
  }

  // Auto-categorizzazione transazione (regex case-insensitive, priority ordering)
  export function categorizeTransaction(description: string, creditorName: string, amount: number): { category: string; icon: string } {
    const text = `${description || ""} ${creditorName || ""}`.toUpperCase();

    const rules = [
      { pattern: /STIPEND|SALARIO|PAGA\b|RETRIBUZ/,             category: "Stipendi",        icon: "👥" },
      { pattern: /AFFITT|LOCAZIONE|FITTO|CANONE IMMOB/,         category: "Affitti",         icon: "🏠" },
      { pattern: /F24|IRPEF|IVA|INPS|INAIL|TRIB|IMPOST|ERARIO/, category: "Tasse",           icon: "📄" },
      { pattern: /FORNI|SUPPLIER|VENDOR|ACQUISTO MERCE/,         category: "Fornitori",       icon: "📦" },
      { pattern: /LUCE|ENERGIA|GAS|ACQUA|TELEF|INTERNET|TIM\b|WIND|ENEL|ENI/, category: "Utenze", icon: "⚡" },
      { pattern: /ASSICURAZ|INSURANCE|ALLIANZ|GENERALI|UNIPOL/, category: "Assicurazioni",   icon: "🛡️" },
      { pattern: /BANCA|COMMISSIONE|SPESE BANCA|INTERESSI|MUTUO/, category: "Bancario",      icon: "🏦" },
      { pattern: /AMAZON|GOOGLE|MICROSOFT|ABBONAMENTO|SUBSCRIPTION/, category: "Servizi",    icon: "💼" },
      { pattern: /RISTORANTE|BAR|CAFFE|PRANZO|CENA|MENSA/,      category: "Ristorazione",   icon: "🍽️" },
      { pattern: /VIAGGIO|HOTEL|AEREO|TRENO|AUTONOLEGGIO|UBER/, category: "Trasferte",       icon: "✈️" },
    ];

    for (const rule of rules) {
      if (rule.pattern.test(text)) {
        return { category: rule.category, icon: rule.icon };
      }
    }

    // Default basato sul tipo
    return amount > 0
      ? { category: "Entrata", icon: "💰" }
      : { category: "Non categorizzata", icon: "❓" };
  }

EDGE FUNCTION 5: `supabase/functions/bank-sync/index.ts`
────────────────────────────────────────────────────────────────────────────────

Sincronizza saldi e transazioni. Chiamata manualmente o da scheduler.

INPUT: { company_id?: string }  ← se omesso usa quello del caller

LOGICA:
  1. Auth check → company_id (dal profilo, o dal body se super_admin)
  2. INSERT bank_sync_logs { sync_type:'manual', status:'running', triggered_by }
     → salva syncLogId
  3. token = await getGoCardlessToken()
  4. Fetch tutte bank_connections WHERE company_id = ? AND status = 'active'
  5. Per ogni connessione, fetch bank_accounts WHERE connection_id = ? AND is_active = true
  6. Per ogni account (sequential per rispettare rate limits GoCardless):
     a. BALANCES:
        balances = await gcFetch(`/accounts/${external_account_id}/balances/`, token)
        UPDATE bank_accounts SET current_balance, available_balance, balance_updated_at=now()

     b. TRANSAZIONI:
        // Calcola date_from: last_sync_at della connection - 1 giorno (per overlapping sicuro)
        const dateFrom = lastSyncAt
          ? new Date(lastSyncAt.getTime() - 86400000).toISOString().split('T')[0]
          : new Date(Date.now() - 90 * 86400000).toISOString().split('T')[0];  // 90 gg se prima sync

        txData = await gcFetch(
          `/accounts/${external_account_id}/transactions/?date_from=${dateFrom}&date_to=${today}`,
          token
        )
        → { transactions: { booked: [...], pending: [...] } }

        Per ogni transazione in booked + pending:
          - amount = parseFloat(tx.transactionAmount.amount)  // può essere negativo
          - txType = amount > 0 ? 'credit' : 'debit'
          - cat = categorizeTransaction(tx.remittanceInformationUnstructured, tx.creditorName, amount)
          - INSERT bank_transactions ON CONFLICT (company_id, external_transaction_id) DO NOTHING
            { company_id, account_id, external_transaction_id: tx.transactionId || tx.internalTransactionId,
              booking_date: tx.bookingDate, value_date: tx.valueDate,
              amount, currency: tx.transactionAmount.currency || 'EUR',
              description: tx.remittanceInformationUnstructured,
              creditor_name: tx.creditorName, debtor_name: tx.debtorName,
              creditor_iban: tx.creditorAccount?.iban, debtor_iban: tx.debtorAccount?.iban,
              reference: tx.entryReference,
              transaction_type: txType, status: txStatus,
              category: cat.category, category_icon: cat.icon,
              metadata: { raw: tx } }
          - Incrementa transactions_fetched

     c. GESTIONE ERRORI PER SINGOLO ACCOUNT:
        Se un account fallisce (catch), logga l'errore ma continua con gli altri.
        Accumula errori in un array, poi inserisci nel sync log come partial error.

  7. UPDATE bank_connections SET last_sync_at=now() per ogni connessione processata
  8. UPDATE bank_sync_logs SET status='success', accounts_synced, transactions_fetched, completed_at=now()
     (se ci sono stati errori su alcuni account: status='partial')
  9. Return { success: true, accounts_synced, transactions_fetched }

RATE LIMITS:
  - Attendi 500ms tra un account e l'altro (avoid 429 Too Many Requests)
  - Se ricevi 429: attendi 60 secondi e riprova una volta
  - Non sincronizzare lo stesso account più di 4 volte al giorno

  Colonne:
  1. Data (booking_date, DD/MM/YYYY)
  2. Descrizione (description · sotto: creditor_name o debtor_name in grigio xs)
  3. Conto (account display_name || account_name)
  4. Categoria (Badge colorato con emoji icon: "📦 Fornitori", "🏠 Affitti", ecc.)
  5. Tipo (Badge verde "↑ Entrata" o rosso "↓ Uscita")
  6. Importo (allineato destra · bold · verde se credit, rosso se debit · formattato EUR)

  Click su riga → apre Sheet laterale (Sheet da shadcn/ui, side="right"):
    Titolo: "Dettaglio Transazione"
    Campi: tutti i dati (booking_date, value_date, amount, description,
           creditor_name, debtor_name, creditor_iban, debtor_iban, reference, status)
    Campo categoria editabile:
      Select con categorie predefinite + "Personalizzata"
      Al cambio: UPDATE bank_transactions SET category = ? WHERE id = ?
    Campo nota:
      Textarea, al blur: UPDATE bank_transactions SET note = ? WHERE id = ?
    (Future) Pulsante placeholder "Collega a Fattura" (disabled, tooltip "In arrivo")
    (Future) Pulsante placeholder "Collega a Costo" (disabled, tooltip "In arrivo")

================================================================================

Dopo aver completato e testato i prompt 1-6, implementa la sync automatica.

OPZIONE A — Supabase pg_cron (se il piano lo supporta):
  SELECT cron.schedule(
    'bank-sync-nightly',
    '0 3 * * *',  -- ogni notte alle 3:00 UTC
    $$
    SELECT net.http_post(
      url := 'https://{PROJECT_REF}.supabase.co/functions/v1/bank-sync-all-companies',
      headers := '{"Authorization": "Bearer {SERVICE_ROLE_KEY}"}'::jsonb,
      body := '{}'::jsonb
    );
    $$
  );

OPZIONE B — Crea edge function `bank-sync-all-companies` chiamata da cron esterno:
  1. Autenticazione tramite header Authorization con service role key
  2. SELECT DISTINCT company_id FROM bank_connections WHERE status = 'active'
  3. Per ogni company_id: invoke bank-sync con { company_id }
  4. Log risultati
