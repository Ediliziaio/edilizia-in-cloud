# Planimetrie — il 3D (fase 5a)

Dal modello della pianta (docs/planimetrie/modello.md) a un volume 3D da girare nel
browser, da esportare (GLB, OBJ) e da fotografare per il render AI (fase 5b).

```
Planimetria ──pianteDaPlanimetria──▶ { fatto, progetto }: PiantaPer3D
                                         │
                                         └─costruisciScena(pianta, { vista, soffitto, elementi })──▶ Scena3D
                                                                     ├─▶ Vista3D (three.js, pigra)
                                                                     ├─▶ esportaGlb / esportaObj
                                                                     └─▶ catturaFotogramma + metadatiFotogramma
```

## Dove sta

| File | Cosa |
|---|---|
| `src/lib/planimetrie/tred/` | parte **pura**, senza three.js: geometria, telecamere, metadati, esportazioni. Gira anche in Node/Deno. |
| `adattatore.ts` | l'unico file che conosce il modello della fase 1 |
| `muri.ts` | incroci (a 45°, a T, a croce) e muro estruso con i vani |
| `scena.ts` | muri, vani, vetri, tamponamenti, pavimenti, soffitti, arredi → `Scena3D` |
| `telecamera.ts` | dall'alto, giro intorno, «entra nella stanza», proiezione, aperture inquadrate |
| `esporta.ts` | GLB (glTF 2.0 binario) e OBJ + MTL, scritti a mano |
| `src/components/planimetrie/Vista3D.tsx` | il visore (three.js + OrbitControls) |
| `src/components/planimetrie/Vista3DPigra.tsx` | **l'unico ingresso** per le pagine dell'app: carica three.js solo quando serve |
| `src/components/planimetrie/tred/fotogramma.ts` | PNG di una vista + metadati, per il render AI |
| `dev/planimetria-3d/` | pagina di prova: `bun run dev`, poi `/dev/planimetria-3d/index.html` (`?esempio=trilocale`) |

## Convenzioni

- Scena in **metri**, **Y verso l'alto** (come glTF e three.js). Il punto (x, y) del
  modello va in (x/100, 0, −y/100): dall'alto, col «su» dello schermo verso −Z, si rivede
  la pianta com'è disegnata.
- Una mesh per oggetto della pianta, col nome leggibile («Muro m1», «Pavimento Bagno»,
  «WC e2»): Blender li mostra così nell'elenco degli oggetti. `riferimento` = id
  dell'oggetto del modello (nel GLB sta in `extras`).
- **Viste**: `fatto` (muri esistenti e da demolire), `progetto` (esistenti e nuovi),
  `confronto` (tutto: giallo = da demolire, rosso = nuovo). Una porta nuova in un muro
  esistente ha le spallette gialle (si demolisce la muratura); una porta da chiudere
  diventa un tamponamento rosso.
- Gli **elementi** sono blocchi semplici (`elementi.ts`): `letto_matrimoniale`,
  `cucina_lineare`… prendono il modello della prima parola conosciuta; un tipo ignoto è
  un parallelepipedo 60×60×80. Rotazione del modello: antioraria, retro verso il basso
  della pianta a 0° (come negli esempi della fase 1: il wc contro il muro in alto ha 180°).
- Un livello per volta, alla sua quota zero.

## Fotogramma per il render AI (fase 5b)

```ts
const cattura = await caricaFotogramma();            // da Vista3DPigra: carica three.js
const { png, metadati } = await cattura({ pianta: progetto, localeId, telecamera });
```

oppure, dal visore aperto, `ref.current.fotogramma()` con la telecamera di adesso.
`metadati` contiene il locale (superficie, perimetro, altezza, larghezza × profondità),
la telecamera, e le **aperture inquadrate** con tipo, misure, riquadro nell'immagine
(frazioni 0–1, origine in alto a sinistra), «sinistra/centro/destra» e distanza.
`metadatiFotogramma` è pura: si può calcolare anche lato server.

## Peso
