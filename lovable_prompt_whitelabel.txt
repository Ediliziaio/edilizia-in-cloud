================================================================================
PROMPT — WHITE LABEL COME FUNZIONE A PAGAMENTO (ADDON SUPERADMIN)
================================================================================
Progetto: Gestionale SaaS multi-tenant (Supabase + React + TypeScript)
Obiettivo: Trasformare il white-label in un ADDON a pagamento, attivabile
           SOLO dal SuperAdmin per singola azienda, con configurazione
           completa di branding (colori, logo, nome piattaforma).

Stato attuale: esiste solo logo_url su companies. Nessun sistema white-label.
Pattern esistente da seguire: messaging_beta_enabled (boolean su companies,
                               toggle nel CompanyDetail del SuperAdmin).

Implementa i 4 prompt IN SEQUENZA.

================================================================================
PROMPT 1 — DATABASE: COLONNE WHITE-LABEL + ADDON TRACKING
================================================================================

Crea la seguente migrazione SQL:

```sql
-- ============================================================
-- AGGIUNTE ALLA TABELLA companies
-- ============================================================

-- Flag principale (solo SuperAdmin può attivarlo)
ALTER TABLE public.companies
  ADD COLUMN IF NOT EXISTS white_label_enabled BOOLEAN NOT NULL DEFAULT false;

-- Branding personalizzato (usato solo se white_label_enabled = true)
ALTER TABLE public.companies
  ADD COLUMN IF NOT EXISTS brand_primary_color TEXT DEFAULT '#1E40AF',
  ADD COLUMN IF NOT EXISTS brand_secondary_color TEXT DEFAULT '#3B82F6',
  ADD COLUMN IF NOT EXISTS brand_accent_color TEXT DEFAULT '#DBEAFE',
  ADD COLUMN IF NOT EXISTS brand_text_on_primary TEXT DEFAULT '#FFFFFF',
  ADD COLUMN IF NOT EXISTS brand_platform_name TEXT DEFAULT NULL,
  -- Nome mostrato nella navbar/sidebar al posto del default della piattaforma
  -- es. "GestionaleProX" invece di "EdiliziaInCloud"
  ADD COLUMN IF NOT EXISTS brand_favicon_url TEXT DEFAULT NULL,
  -- URL favicon personalizzata
  ADD COLUMN IF NOT EXISTS brand_login_bg_url TEXT DEFAULT NULL,
  -- Immagine di sfondo della pagina di login
  ADD COLUMN IF NOT EXISTS brand_hide_powered_by BOOLEAN DEFAULT false;
  -- Se true, nasconde "Powered by [piattaforma]" nel footer

-- Tracking addon (per storico e billing)
ALTER TABLE public.companies
  ADD COLUMN IF NOT EXISTS white_label_enabled_at TIMESTAMPTZ DEFAULT NULL,
  ADD COLUMN IF NOT EXISTS white_label_enabled_by UUID REFERENCES auth.users(id) DEFAULT NULL,
  ADD COLUMN IF NOT EXISTS white_label_monthly_price NUMERIC(8,2) DEFAULT 0;
  -- Prezzo mensile personalizzato per questo addon (es. 49.00)

-- ============================================================
-- TABELLA: company_addons_log
-- Storico di attivazione/disattivazione addon per le aziende
-- ============================================================
CREATE TABLE IF NOT EXISTS company_addons_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id UUID NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
  addon_key TEXT NOT NULL,
  -- 'white_label' | 'messaging_beta' | future addons
  action TEXT NOT NULL,
  -- 'enabled' | 'disabled' | 'price_changed' | 'branding_updated'
  performed_by UUID REFERENCES auth.users(id),
  performed_by_email TEXT,
  old_value JSONB,
  new_value JSONB,
  notes TEXT,
  -- Note interne del SuperAdmin (es. "Cliente ha pagato €49/mese")
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE company_addons_log ENABLE ROW LEVEL SECURITY;

-- Solo SuperAdmin può leggere il log
CREATE POLICY "super_admins_manage_addons_log"
ON company_addons_log FOR ALL
TO authenticated
USING (
  EXISTS (
    SELECT 1 FROM user_roles
    WHERE user_id = auth.uid() AND role = 'super_admin'
  )
);

-- ============================================================
-- STORAGE BUCKET per assets white-label
-- ============================================================
INSERT INTO storage.buckets (id, name, public)
VALUES ('white-label-assets', 'white-label-assets', true)
-- public = true perché favicon e bg login devono essere accessibili
-- senza autenticazione (pagina di login pubblica)
ON CONFLICT (id) DO NOTHING;

CREATE POLICY "company_members_upload_wl_assets"
ON storage.objects FOR INSERT TO authenticated
WITH CHECK (
  bucket_id = 'white-label-assets' AND
  (storage.foldername(name))[1] = (
    SELECT company_id::text FROM profiles WHERE id = auth.uid()
  )
);

CREATE POLICY "public_read_wl_assets"
ON storage.objects FOR SELECT TO anon, authenticated
USING (bucket_id = 'white-label-assets');

-- ============================================================
-- RLS AGGIORNATA PER companies (aggiunge white_label_enabled)
-- I campi white-label sono leggibili dall'azienda stessa
-- ma modificabili SOLO da super_admin
-- ============================================================
-- (Le policy esistenti già coprono SELECT per company members)
-- Aggiungi funzione helper per verifica superadmin:
CREATE OR REPLACE FUNCTION is_super_admin(p_user_id UUID DEFAULT auth.uid())
RETURNS BOOLEAN AS $$
  SELECT EXISTS (
    SELECT 1 FROM user_roles
    WHERE user_id = p_user_id AND role = 'super_admin'
  );
$$ LANGUAGE SQL SECURITY DEFINER STABLE;
```

### HOOK: useBrandSettings.ts

Crea: src/hooks/useBrandSettings.ts

```typescript
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { supabase } from '@/integrations/supabase/client';
import { useAuth } from '@/contexts/AuthContext';

export interface BrandSettings {
  white_label_enabled: boolean;
  brand_primary_color: string;
  brand_secondary_color: string;
  brand_accent_color: string;
  brand_text_on_primary: string;
  brand_platform_name: string | null;
  brand_favicon_url: string | null;
  brand_login_bg_url: string | null;
  brand_hide_powered_by: boolean;
  logo_url: string | null;
}

export function useBrandSettings(companyId?: string) {
  const { company } = useAuth();
  const id = companyId ?? company?.id;
  const queryClient = useQueryClient();

  const { data: brand } = useQuery({
    queryKey: ['brand-settings', id],
    queryFn: async () => {
      const { data } = await supabase
        .from('companies')
        .select(`
          white_label_enabled,
          brand_primary_color,
          brand_secondary_color,
          brand_accent_color,
          brand_text_on_primary,
          brand_platform_name,
          brand_favicon_url,
          brand_login_bg_url,
          brand_hide_powered_by,
          logo_url
        `)
        .eq('id', id!)
        .single();
      return data as BrandSettings;
    },
    enabled: !!id,
    staleTime: 5 * 60 * 1000, // cache 5 minuti
  });

  const saveBrand = useMutation({
    mutationFn: async (updates: Partial<BrandSettings>) => {
      const { error } = await supabase
        .from('companies')
        .update(updates)
        .eq('id', id!);
      if (error) throw error;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['brand-settings', id] });
      queryClient.invalidateQueries({ queryKey: ['company', id] });
    },
  });

  // Shortcut: colori effettivi (fallback se non white-label)
  const effectiveBrand = {
    primaryColor: brand?.white_label_enabled ? (brand.brand_primary_color ?? '#1E40AF') : '#1E40AF',
    secondaryColor: brand?.white_label_enabled ? (brand.brand_secondary_color ?? '#3B82F6') : '#3B82F6',
    accentColor: brand?.white_label_enabled ? (brand.brand_accent_color ?? '#DBEAFE') : '#DBEAFE',
    textOnPrimary: brand?.white_label_enabled ? (brand.brand_text_on_primary ?? '#FFFFFF') : '#FFFFFF',
    platformName: brand?.white_label_enabled ? (brand.brand_platform_name ?? null) : null,
    logoUrl: brand?.logo_url ?? null,
    faviconUrl: brand?.white_label_enabled ? (brand.brand_favicon_url ?? null) : null,
    loginBgUrl: brand?.white_label_enabled ? (brand.brand_login_bg_url ?? null) : null,
    hidePoweredBy: brand?.white_label_enabled ? (brand.brand_hide_powered_by ?? false) : false,
    isWhiteLabel: brand?.white_label_enabled ?? false,
  };

  return { brand, effectiveBrand, saveBrand };
}
```

### A — CSS VARIABLES DINAMICHE (CompanyLayout.tsx)

In src/components/layouts/CompanyLayout.tsx, nel componente principale,
aggiungi un useEffect che inietta i colori come CSS variables nell'elemento :root:

```typescript
import { useBrandSettings } from '@/hooks/useBrandSettings';

// All'interno del componente:
const { effectiveBrand } = useBrandSettings();

useEffect(() => {
  if (effectiveBrand.isWhiteLabel) {
    const root = document.documentElement;
    root.style.setProperty('--brand-primary', effectiveBrand.primaryColor);
    root.style.setProperty('--brand-secondary', effectiveBrand.secondaryColor);
    root.style.setProperty('--brand-accent', effectiveBrand.accentColor);
    root.style.setProperty('--brand-text-on-primary', effectiveBrand.textOnPrimary);
  } else {
    // Rimuovi le variabili custom se white-label disattivato
    const root = document.documentElement;
    root.style.removeProperty('--brand-primary');
    root.style.removeProperty('--brand-secondary');
    root.style.removeProperty('--brand-accent');
    root.style.removeProperty('--brand-text-on-primary');
  }
}, [effectiveBrand]);
```

NOTE IMPORTANTI
================================================================================

- La modifica dei colori tramite CSS variables è SOLO per elementi
  che usano var(--brand-primary) nel CSS. Non cambierà i componenti
  shadcn/ui che usano classi Tailwind hardcoded come `bg-blue-600`.
  Usa inline style per gli elementi principali (sidebar header, active items,
  bottoni principali, badge).

- Se il progetto usa Tailwind CSS con JIT, non è possibile generare classi
  dinamiche come `bg-[#991B1B]`. Usa SEMPRE inline style per i colori brand.

- Il logo rimane funzionante anche senza white-label (logo_url è gratuito).
  Il white-label sblocca SOLO: colori, nome piattaforma, favicon, bg login,
  rimozione "Powered by".

- Gestisci sempre il caso in cui effectiveBrand sia undefined/null durante
  il caricamento (usa i colori di default come fallback).

- NON modificare la logica di autenticazione, permessi o ordini.
  Modifica SOLO: CompanyDetail admin, SettingsProfile azienda, layout components.
